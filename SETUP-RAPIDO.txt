CHAMPIONS BOLÃO — SETUP RÁPIDO

1) SUPABASE — BANCO E SEGURANÇA
   - Abra seu projeto no Supabase.
   - SQL Editor > New query.
   - Cole TODO o conteúdo de supabase/setup.sql e clique em Run.
   - Se você já executou uma versão anterior do setup.sql, pode executar a versão nova inteira novamente.

2) SUPABASE — AUTH
   - Desative cadastro público: Authentication > Sign In / Providers > Email > Allow new users to sign up = OFF (o nome exato pode variar na interface).
   - Deixe Allow anonymous sign-ins = OFF.
   - Continue criando usuários manualmente por Authentication > Users > Add user.

3) CRIE OS USUÁRIOS EM AUTHENTICATION > USERS
   Exemplos iniciais:
   leandro@champions-bolao.app
   caio@champions-bolao.app
   joao@champions-bolao.app
   matheus@champions-bolao.app
   leonardo@champions-bolao.app
   bruno@champions-bolao.app

   Crie cada um com senha e como usuário confirmado.
   Leandro vira admin automaticamente pelo trigger do banco.
   Você pode criar novos usuários manualmente no painel do Supabase mesmo com cadastro público desligado.
   Para o login por nome funcionar, use o padrão usuario@champions-bolao.app.
   Exemplo: pedro@champions-bolao.app -> login: pedro.

4) DESENVOLVIMENTO LOCAL
   - Copie .env.example para .env.local.
   - Preencha SOMENTE:
       VITE_SUPABASE_URL
       VITE_SUPABASE_PUBLISHABLE_KEY
   - Nunca use service_role, sb_secret, senha do banco ou outros segredos em variável VITE_*.

   Depois execute:
   npm install
   npm run dev

5) VERCEL
   Em Project > Settings > Environment Variables, cadastre:
   - VITE_SUPABASE_URL
   - VITE_SUPABASE_PUBLISHABLE_KEY

   O arquivo .env real NÃO faz parte deste ZIP e está bloqueado no .gitignore.

6) LOGIN
   Digite só o primeiro nome (ex.: leandro), e não o email inteiro.

IMPORTANTE
- A publishable key é própria para uso no frontend; a proteção dos dados depende de grants + RLS.
- Este projeto revoga acesso do role anon às tabelas e aplica RLS.
- O setup também revoga privilégios automáticos para NOVOS objetos no schema public, evitando exposição acidental futura.
- Nunca coloque service_role / sb_secret / senha do Postgres no React, GitHub ou em variável VITE_*.
